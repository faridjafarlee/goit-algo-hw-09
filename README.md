# goit-algo-hw-09

# Жадібні алгоритми та динамічне програмування - видача решти

## Завдання
Реалізовано дві функції для видачі решти набором монет `[50, 25, 10, 5, 2, 1]`:

- `find_coins_greedy(amount)` - жадібний алгоритм (беремо найбільший номінал, який поміщається).
- `find_min_coins(amount)` - динамічне програмування (знаходимо мінімальну кількість монет).

## Приклад
Для `amount = 113`:
- Greedy: `{50: 2, 10: 1, 2: 1, 1: 1}`
- DP: `{1: 1, 2: 1, 10: 1, 50: 2}`

## Аналіз ефективності

### Жадібний алгоритм
- Ідея: завжди беремо найбільшу монету, яка не перевищує залишок.
- Часова складність: **O(k)**, де `k` - кількість номіналів (у нас `k=6`, фактично константа).
- Пам'ять: **O(1)**.
- Дуже швидкий на великих сумах, бо робить фіксовану кількість операцій.

### Динамічне програмування
- Ідея: рахуємо мінімальну кількість монет для кожної суми від `0` до `amount`.
- Часова складність: **O(amount * k)**.
- Пам'ять: **O(amount)** (масиви `dp` та `prev`).
- На великих сумах працює повільніше і споживає більше пам'яті, бо мусить заповнити таблицю до `amount`.

## Висновок
Для великих сум більш ефективним є **жадібний алгоритм**, бо має фактично константний час для фіксованого набору монет і не потребує додаткової пам'яті.

ДП виграє за універсальністю: він гарантує мінімальну кількість монет навіть для "незручних" наборів номіналів, де жадібний підхід може помилятися. Але ціна - лінійна залежність від суми за часом і пам'яттю.
